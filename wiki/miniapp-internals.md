# Мини-приложение изнутри

Папка `miniapp/`. Бэкенд — FastAPI + SQLite, фронтенд — чистый HTML/CSS/JS без сборки, всё в
одном Docker-образе за Caddy. Подробная инструкция — `miniapp/README.md`.

## Состав

| Файл | Что |
|---|---|
| `backend/app/main.py` | эндпоинты API и раздача фронтенда |
| `backend/app/lots.py` | логика ленты: текущая цена и срок, процент, видимость, фильтры, сортировка, фасеты, машины и избранное, чистка марок и моделей |
| `backend/app/db.py` | SQLite: таблицы и запросы |
| `backend/app/auth.py` | проверка подписи Telegram initData |
| `backend/app/bot.py` | бот @honestlot_bot (отдельный сервис) |
| `backend/app/telegram.py` | вызовы Bot API через релей |
| `backend/app/watchdog.py` | сторож выгрузок |
| `backend/app/status_refresh.py` | статус торгов на агрегаторе и ЭТП, несколько раз в день |
| `backend/app/etp_collect.py` | новые лоты прямо с площадок (разбор — `etp_lots.py` в корне) |
| `backend/app/backup.py` | ежедневная копия базы |
| `backend/app/stats.py` | сводка по пользователям и активности |
| `frontend/app.js`, `style.css`, `index.html` | интерфейс |
| `frontend/telegram-web-app.js` | копия официального скрипта Telegram |
| `docker-compose.yml`, `Caddyfile`, `.env.example`, `deploy.sh` | сервер |
| `run_local.py` | локальный запуск |

Общие модули из корня репозитория `lot_metrics.py` и `bidding_schedule.py` копируются в образ.

## API

Все `/api/*`, кроме служебных, требуют заголовок `Authorization: tma <initData>` (мини-апп в
Telegram) или `Authorization: web <токен>` (веб-версия в браузере, см. «Авторизация»).

| Метод | Путь | Что |
|---|---|---|
| GET | `/api/lots` | лента: фильтры, сортировка, `offset`, `limit` (до 50; `limit=0` — только число) |
| GET | `/api/facets` | варианты для экрана фильтров (марки, модели, регионы, годы) |
| GET | `/api/lots/{id}` | экран лота (пишет событие `lot_view`) |
| GET | `/api/favorites` | избранное пользователя |
| PUT / DELETE | `/api/favorites/{id}` | добавить / убрать |
| GET | `/api/me` | код пользователя для ссылок «Поделиться» |
| POST | `/api/events` | событие `open`, `source_click`, `share`, `paywall`, `paywall_go`, `notify_open` (открыли из уведомления: `notify` / `email`) |
| GET / POST / PATCH / DELETE | `/api/searches`, `/api/searches/{id}` | сохранённые поиски (Pro): список с числом лотов и новыми, сохранить, переименовать / фильтры / уведомления, удалить |
| GET | `/api/searches/preview` | имя и число лотов для окна «Сохранить поиск» |
| POST | `/api/searches/{id}/open` | поиск открыт: его новые лоты просмотрены |
| GET / POST | `/api/notify/settings` | каналы уведомлений: `tg`, `fav_events`, `email_on` |
| POST | `/api/notify/email` | почта для писем: ссылка подтверждения |
| GET | `/notify/confirm?t=` | подтверждение почты (страница) |
| GET / POST | `/notify/unsubscribe?t=` | отписка от писем: страница с кнопкой, по GET ничего не меняется (почтовые сканеры), POST — и из почты (List-Unsubscribe) |
| GET | `/api/health` | `{"ok": true, "lots": N}` — без авторизации, N — лотов в базе всего |

Служебные — с заголовком `X-Import-Token` (= `HONESTLOT_IMPORT_TOKEN`):

| Метод | Путь | Что |
|---|---|---|
| POST | `/api/import` | выгрузка лотов с ПК (шаг 8). Чего в выгрузке нет, уходит из ленты, поэтому выгрузку, которая скрыла бы больше половины ленты (лента от 100 лотов), сервер не принимает (409); настоящее сокращение — `?force=1` (`export_to_miniapp.py --force`) |
| GET | `/api/watchlist` | лоты из избранного без итога торгов |
| POST | `/api/lot-status` | статусы, перечитанные с сайта |
| GET | `/api/backup` | свежая копия базы |

## Авторизация

Telegram передаёт мини-аппу `initData` (пользователь, `auth_date`, `start_param`, подпись).
Сервер проверяет подпись токеном бота (`HONESTLOT_BOT_TOKEN`) — подделать `telegram_id` нельзя.
`initData` старше 7 дней не принимается — пользователь видит заглушку и должен переоткрыть
приложение. Логинов и паролей нет. Локально без Telegram запросы идут от пользователя
`HONESTLOT_DEV_USER_ID` (на сервере не задаётся).

**Веб-версия** (honestlot.ru в обычном браузере, с 13.10.2026): `initData` нет. `app.js`
определяет браузер по `Telegram.WebApp.platform == "unknown"` и показывает вход через Telegram
Login Widget (домен бота в @BotFather — `honestlot.ru`). `POST /api/web-login` проверяет подпись
виджета (`auth.validate_login_widget`, не старше суток) и выдаёт **токен входа на 30 дней**
(`auth.make_web_token`: id, username, имя и срок, подпись HMAC ключом `HONESTLOT_WEB_SECRET` или
производным от токена бота — смена токена бота разлогинит всех на сайте). Токен хранится в
`localStorage` (`hl_web_token`), запросы — с `Authorization: web <токен>`. Пользователь тот же,
что в мини-аппе: избранное общее; новым пользователям сайта `users.source = "web"`. Тот же токен
принимает страница оплаты (`billing.user_from_header`). Главная отдаётся с `X-Robots-Tag:
noindex` и метатегом `robots`.

**Pro в веб-версии:** без подписки фильтры и избранное закрыты окном «Перейти на Pro»
(`app.js`: `locked`, `showPaywall`), признак — поле `pro` в `GET /api/me` (есть, только когда
оплата включена). Закрыто только в интерфейсе: API фильтры и избранное не ограничивает. Показ окна
и нажатие «Перейти на Pro» пишутся в `events` как `paywall` / `paywall_go` (`source` — `filters`
или `favs`), итог — в `python -m app.stats`.

## База (SQLite, `/data/honestlot.db` в контейнере, `miniapp/data/` на сервере)

| Таблица | Что |
|---|---|
| `lots` | все когда-либо выгруженные лоты. Ушедшие из выгрузки не удаляются (`in_source = 0`): на них ссылаются избранное и история машины |
| `users` | `telegram_id`, `username`, `first_name`, даты, `source` (первая метка `startapp`), `last_source`, `ref_code` (случайный код для «Поделиться»), `referred_by` (кто привёл) |
| `favorites` | `telegram_id`, `lot_id`, `vin` машины, дата |
| `events` | `open`, `lot_view`, `fav_add`, `source_click`, `share`, `search_save`, `notify_open`, … |
| `saved_searches` | сохранённые поиски: `telegram_id`, `name` (пусто — из фильтров), `params` (JSON, параметры ленты), `notify`, `opened_at` |
| `notify_seen` | машины (VIN или `lot:<номер>`), о которых пользователь уже знает: из выдачи при сохранении поиска или из уведомления — повторов не бывает |
| `notify_events` | события уведомлений (`search`, `relisted`, `price_down`) и их доставка в Telegram и почту |
| `notify_settings` | каналы пользователя: Telegram разрешён / бот заблокирован, почта и её подтверждение, события избранного |
| `fav_watch` | последнее известное по машине из избранного: главный лот, открыт ли, цена |
| `catalog_fixes` | ручные правки справочника марок и моделей (`catalog.py`) |

Невосстановимое — пользователи, избранное, события. Лоты восстанавливаются следующей выгрузкой.

## Логика ленты (`lots.py`)

- Кэш всех лотов в памяти, сбрасывается после каждого импорта. Фильтры и сортировка — в памяти.
- **Текущая цена и срок** — `bidding_schedule.effective_price_and_deadline` на момент запроса.
  Выгрузка присылает для ПП **окончательный** срок, текущий этап сервер выбирает сам.
- **Процент** — `lot_metrics.gap_percent` от текущей цены; у мультилота нет.
- **Лот открыт** (`is_open`): есть в последней выгрузке, срок в будущем, статус не закрытый, тип
  не право требования и не доля.
- **Машина** (`lot["car"]`) — VIN из 17 знаков у лота типа «одна машина». Открытые лоты одной
  машины — одна карточка (`_primary_key`: дешевле → раньше срок → ЭТП, а не «вне ЭТП»).
- **Итог торгов** (`outcome`) — по тексту статуса: «не состоял» → `failed`, «заверш» → `done`,
  «отмен»/«аннулир» → `cancelled`, «приостанов» → `suspended`, «удал» → `removed`; иначе
  `open` или `awaiting`.
- **Избранное** следует за машиной: в `favorites` и `lot_id`, и VIN. Карточка избранного —
  актуальный лот машины (открытый, иначе последний), `relisted` — машина выставлена снова,
  `archived` — закрыта больше 60 дней назад. Удаление убирает все лоты машины.
- **Watchlist:** лоты избранного (и всех лотов избранных машин) с прошедшим сроком без
  окончательного итога, не дольше 60 дней после срока, не чаще раза в 20 часов.
- **Марки и модели:** алиасы (VAZ → Lada, Mercedes → Mercedes-Benz, Кадилак → Cadillac, Черри →
  Chery, Роллс-Ройс → Rolls-Royce), поиск известной марки во фразе («Тс: Фольксваген»), модель из
  названия после марки и после слова «модель» («ГАЗ, модель: 3302»), коды Авто.ру («M_KLASSE» →
  «M-класс», «5ER» → «5 серии», «CR_V» → «CR-V»), привязка моделей из названия к словарю Авто.ру
  (`build_catalog`, `snap_model`: «Солярис» → Solaris). Чистка — здесь, а не в таблице.
  С 22.10.2026: если оценка без цены (не определила машину однозначно), её модель — догадка; когда в названии
  лота другое слово-модель («sprinter 2» против CL-класса), показывается модель из названия
  (`_guess_contradicts_title`), а словарь моделей учится только на оценках с ценой.
- **Справочник (`catalog.py`, с 18.10.2026):** после разбора модель проходит через ручные правки
  из базы (таблица `catalog_fixes`), семейства (`FAMILIES`: Lada 2121/2131/Niva Legend → Niva,
  2170 → Priora, 2108–2115 → Samara; ГАЗ 3302/2705/3221 → ГАЗель, A21R… → ГАЗель Next, 2752 →
  Соболь; УАЗ 23632 → Pickup; Hyundai H-100 → Porter) и единые подписи (`LABELS`: RAV4, Santa Fe,
  ASX, Hover H3…). Решение владельца: варианты одной модели — одна модель, мусор разбирать вручную.
  Раз в месяц (сторож выгрузок, первая проверка после 10:00 1-го числа, состояние в
  `data/catalog_check.json`) администратору приходит сводка: лоты без марки и без модели, модели
  кириллицей, похожие на мусор, коды из цифр, похожие модели одной марки. Разбор — командами на ВМ
  (`docker compose exec api python -m app.catalog ...`): `fix <lot_id|VIN> "Марка" "Модель"`,
  `rename "Марка" "модель" "новая"`, `ok <lot_id>` / `ok "Марка" "модель"` (не ошибка — больше не
  показывать), `list`, `del <id>`, без аргументов — сводка сейчас. Правки действуют со следующей
  сборки кэша ленты, выкладка кода не нужна.
- **Поиск по тексту (`text_matches`, с 18.10.2026):** слово запроса совпадает, если с него
  начинается слово марки, модели или названия (кириллические двойники = латиница; 1–2 знака —
  только целым словом; слова с цифрами от 3 знаков — подстрокой, для VIN и госномера); если это
  марка по-русски; если со «скелета» (буквы и цифры, кириллица транслитом) начинается слово или
  пара слов марки/модели («rav4» = RAV 4); если на слух совпадает со словом марки/модели (те же
  согласные, разница в 1 букву, у слов одной длины от 6 букв — в 2: «кулрей» = Coolray, но «камри»
  ≠ Camaro). Весь запрос «скелетом» тоже сверяется с маркой и моделью («мазда 6»). Индекс для поиска
  строится один раз при сборке кэша (`_search_index`). Та же функция будет у сохранённых поисков.
- **«Скрыть битые»** прячет `total_damage`: тотальные слова в названии или вердикт фото `total`.

### ДТП (с 19.10.2026)

Поле `lots.dtp` (JSON из выгрузки, `export_to_miniapp.dtp_payload`): `{count, as_of, accidents: [{date,
type, region, scheme}]}`; пусто — нет данных. Лента отдаёт `dtp_count` (метка «ДТП: N»), экран лота —
`dtp` со ссылками на схемы через `/img` (`imgproxy.ALLOWED_PREFIXES` разрешает
`https://data.tronk.info/img.ashx`). Даты и схемы закрыты Pro только в интерфейсе (`locked("dtp")`),
как фильтры и избранное; событие раскрытия — `dtp_open`.

## Бот @honestlot_bot (`bot.py`)

Отдельный сервис `bot` в docker-compose. Long polling (`getUpdates`) через релей, вебхук при
старте снимается. На любое личное текстовое сообщение — приветствие с кнопкой «Открыть лоты».
Группы, каналы, стикеры игнорирует. Сообщения пользователей не сохраняет и не логирует.

Ссылка с меткой источника: `https://t.me/honestlot_bot?startapp=<метка>` (латиница, цифры, `_`,
`-`, до 64 символов). Метка пишется пользователю в `users.source` при первом входе. Метки вида
`lot<цифры>` заняты ссылками «Поделиться».

## Сохранённые поиски и уведомления (`searches.py`, `notify.py`)

С 19.10.2026, решения владельца: только Pro, вкладка «Поиски», кнопка «Сохранить поиск» в строке
фильтров ленты; «перевыставили» и «цена снизилась» по избранному — да, «итоги торгов» — заморожено;
окна «только днём» нет, только публичные предложения — с 8:00. Включение — `HONESTLOT_SAVED_SEARCHES` в `.env`: пусто — выключено (API 404,
вкладки нет), `all` — всем, список `telegram_id` или `@ников` через запятую — только им (с 19.10.2026 — `all`).

- Поиск — те же параметры, что у ленты; совпадение считает `lots._matches` (как лента), текст —
  `lots.text_matches`. Имя без своего — из фильтров (`searches.describe`; начальная «цена от 300 тыс.»
  в имя не попадает).
- **Без повторов:** `notify_seen` — пара (пользователь, машина); машина — VIN или `lot:<номер>`. При
  сохранении поиска или смене фильтров все подходящие сейчас машины отмечаются известными. Отметка
  и событие пишутся одной транзакцией до отправки. Машины из избранного поиск пропускает.
- **Избранное** (`fav_watch`): «выставлена снова» — снова открыт лот, и это другой лот (тот же после
  паузы «итоги подводятся» — не событие); «цена снизилась» — цена открытого лота ниже известной
  (следующий этап публичного предложения, более дешёвый параллельный лот).
- **Когда:** поток `notify` делает проход сразу после выгрузки с ПК (`POST /api/import`), после
  каждой проверки статусов (`status_refresh.py`: 05, 11, 16, 21) и сам в 08:01 (отложенные ПП) и
  10:01 (письмо).
  Telegram — сразу, кроме публичных предложений: о них (любое событие по лоту ПП) — не раньше 8:00
  по Москве (`PUBLIC_OFFER_FROM_HOUR`, решение владельца 19.10.2026: цена ПП падает ночью, событие
  находит проверка в 05:00), поток сам просыпается в 08:01. До 5 лотов в сообщении, кнопка `web_app` открывает `honestlot.ru/?lot=…`,
  `?search=…` или `?tab=favs`. 403 / «chat not found» — бот заблокирован (`tg_blocked_at`), больше не
  пишем; 429 и нет связи с релеем — повтор при следующем проходе, не дольше суток; таймаут —
  считаем отправленным. Письмо — раз в день после 10:00, с `List-Unsubscribe`.
- **Перерыв:** пользователь не проходил проверку больше 72 ч (кончался Pro) — вместо событий новая
  отметка известных машин, без пачки старого.
- Разрешение писать: мини-апп сначала показывает своё объяснение (`showPopup`), потом
  `requestWriteAccess`; кто уже разрешал (`allows_write_to_pm` в initData), тому ничего не
  показывается. Ссылки из писем подписаны (`billing._link_secret`).
- Проверить локально: `miniapp/run_local.py` (там функция включена; без токена бота сообщения не
  уходят, без SMTP письма — в лог).

## Сторож выгрузок (`watchdog.py`)

Поток в сервисе `api`. Раз в час смотрит время последней выгрузки (самый свежий
`lots.updated_at`). Больше 36 часов — сообщение в `HONESTLOT_ADMIN_CHAT_ID` от бота уведомлений (`HONESTLOT_NOTIFY_BOT_TOKEN`; без него — от @honestlot_bot),
повтор раз в сутки, после восстановления — одно сообщение. Без переменной выключен. Получатель
должен хоть раз нажать «Старт» у @honestlot_bot. На время намеренной остановки конвейера
переменную убрать и перезапустить `api`.

## Статус торгов на ЭТП (`status_refresh.py`)

С 15.10.2026. Агрегатор отстаёт: публичное предложение заканчивается досрочно (кто-то подал
заявку), а агрегатор ещё дни пишет «Идёт приём заявок». Поэтому сервер сам, фоновым потоком в
`api`, в 05:00, 11:00, 16:00 и 21:00 МСК проходит по открытым публичным предложениям ленты и
лотам избранного без итога:

- карточка агрегатора (тот же разбор, что на ПК, `parse_lot.py`) — статус, цена, график, срок,
  ссылка на ЭТП → поля `live_*`. В 05:00 — у всех, в остальные проходы — только у лотов на
  площадках без разбора, чтобы не нагружать агрегатор;
- страница лота на ЭТП (`etp_status.py`) → `etp_state` (`open` / `pending` / `closed`),
  `etp_text`, `etp_outcome`.

Итог на ЭТП важнее агрегатора (`lots._apply_live`): «завершены», «не состоялись», «отменены»,
«приостановлены» — статус лота, лот уходит из ленты, в избранном показывается итог. «Итоги
подводятся» (приём заявок на ЭТП окончен, идёт определение участников) — лот скрыт из ленты, но
не закрыт: если торги продолжатся, следующий проход вернёт его. Данные сервера старше 30 часов не
используются. Импорт с ПК поля `live_*`/`etp_*` не трогает. ПК забирает результат в шаге 1
(`GET /api/lot-statuses`) и пишет в лист `lots`.

Разборы — по движкам площадок: «Статус: …» (ТоргГрупп, ЭТПУ, АРБбитЛот, Центр реализации,
torgibankrot, tender.one), «Статус торгов …» (НИС, Систематорг, «Россия онлайн», Промконсалт,
ELECTRO-TORGI, UralBidIn), ЦДТ, МЭТС, РАД (с 19.10.2026 — блок статуса лота `formMain:opStatus`; «Процедура
по лоту проведена» — торги прошли) и Фабрикант (статус рядом с VIN лота). Новая площадка
на знакомом движке узнаётся по виду ссылки. Статус, который рисует скрипт в браузере (Аукционы
Сибири, Аукцион-центр, Альфалот), не разбираем — для них статус агрегатора. НИС не пускает сервер
(403), с ПК открывается. Часть ЭТП подписана российским сертификатом Минцифры — такие страницы
читаются без проверки сертификата (только чтение).

Сообщения администратору — см. [Уведомления и сбои](runbook.md). Выключить:
`HONESTLOT_STATUS_REFRESH=0` в `.env` (локально выключено в `run_local.py`). Что сообщали —
`miniapp/data/status_refresh_state.json`.

## Лоты прямо с площадок (`etp_collect.py`)

С 16.10.2026, вместе с агрегатором, а не вместо него. С 11.10.2026 агрегатор перестал
публиковать новые лоты, а и раньше пропускал часть: 16.10 на ТоргГрупп по Москве и области было
504 машины, у нас — 342. Сервер фоновым потоком в `api` в 06:00, 14:00 и 20:00 МСК обходит
площадки из `etp_lots.COLLECTORS` (ТоргГрупп, МЭТС, с 19.10.2026 — ЦДТ и Lot-online):

- список лотов площадки: Москва и область, торги объявлены или идёт приём заявок, только машины
  (ТоргГрупп — по названию, `etp_lots.is_vehicle`: как категория агрегатора — легковые и лёгкие
  фургоны; МЭТС, ЦДТ и Lot-online — по категории самой площадки «Легковой автомобиль» / «Легковой транспорт» /
  «Легковые автомобили»);
- лот, который уже есть в ленте от агрегатора (тот же адрес лота на ЭТП), не читается;
- новый лот (или прочитанный больше 3 дней назад) читается целиком: страница лота (статус, цены,
  график снижения, сроки, все фото — оригиналы с площадки, номер сообщения ЕФРСБ, число заявок)
  и страница торгов (организатор, управляющий, должник) → таблица `etp_lots` в базе.

В таблицу Google сервер не пишет: ПК забирает лоты в шаге 1 (`GET /api/etp-lots`,
`main.pull_etp_lots`) и сам дописывает новые. Так нет одновременной записи: ПК во время прогона
удаляет строки и держит номера строк в памяти.

**Номер лота.** По 127-ФЗ машина проходит торги → повторные торги → публичное предложение,
каждые торги — своё сообщение в ЕФРСБ и свой номер на площадке. Строка листа — лот торгов, машина —
VIN (лента собирает лоты одной машины, избранное следует за машиной). Ключ лота с площадки — адрес
его страницы на ЭТП, а не номер ЕФРСБ: изменение объявления публикуется в ЕФРСБ новым сообщением,
а адрес лота не меняется. Номер ЕФРСБ хранится полем `efrsb_number`. `lot_id` = 9 000 000 000 +
код площадки × 10⁸ + номер лота на площадке (ТоргГрупп — код 1: лот 20320 → `9100020320`; МЭТС — код 2, номер лота — номер торгов × 100 + номер лота: `240658-1` → `9224065801`), всегда
тот же для того же лота. Статусы — словами агрегатора («Торги объявлены», «Идёт приём заявок»,
«Приём заявок завершён», «Торги завершены»…).

Статус выгруженных лотов с площадок проверяет `status_refresh.py`: у них читается только
страница лота на площадке, к агрегатору запросов нет.

Новая площадка — класс в `etp_lots.py` (список лотов, страница лота) + запись в `COLLECTORS` и
`PLATFORM_CODES` (код площадки не менять: на нём держатся номера лотов). Сообщения
администратору — см. [Уведомления и сбои](runbook.md). Выключить: `HONESTLOT_ETP_COLLECT=0` в
`.env` (локально выключено в `run_local.py`). Один проход вручную:
`docker compose exec api python -m app.etp_collect`. Итог последнего прохода —
`miniapp/data/etp_collect_state.json`.

## Фото с площадок вместо фото агрегатора

С 16.10.2026. Фото агрегатора — его копии фото площадки с его водяным знаком «Торги России» поверх.
Цели по порядку (решение владельца): **1) фото у как можно большего числа лотов; 2) среди них как
можно меньше фото со знаком агрегатора.** Сервер берёт фото прямо со страницы лота на площадке
(`etp_lots.page_photos`) и показывает их первыми, а фото агрегатора остаются запасными:

| Площадка | Что на фото |
|---|---|
| ТоргГрупп | оригиналы без водяных знаков |
| МЭТС, ЦДТ | знак самой площадки, без знака агрегатора |
| ЦДТ без фото на странице | с 21.10.2026 — из документов торгов («Документы и дополнительные материалы»): документ «Фото ТС», «авто», «фотографии» — обычно PDF со снимком на странице. Сервер (`docphotos.py`) берёт его через открытый API ЦДТ (`Trade/public`, `Doc/public`), вынимает картинки (pypdf; меньше 300 px — печати и логотипы — отбрасывает), хранит у себя с превью и отдаёт `GET /docimg/<имя>`. Это оригиналы без знаков. Сканы (ПТС, СТС, договоры, акты, счета) не берутся. Делает проход фото `etp_collect.photo_pass`; проход статусов пустой страницей ЦДТ такие фото не затирает |
| Lot-online (РАД) | с 21.10.2026 — из карточки каталога catalog.lot-online.ru, которую сборщик Lot-online и так читает при обходе (в том числе для лотов, пришедших от агрегатора): без водяных знаков, но не больше 480×360. Лоты, которых нет в каталоге (другой регион имущества), остаются с фото агрегатора |
| НИС | с 22.10.2026 — фото со страницы торгов (lightbox `images_<номер лота>`): оригиналы с телефона 4000×3000 без знаков. Сервер скачивает до 10 фото лота не чаще раза в 15 с (НИС банит за частые запросы), уменьшает до 1600 px с превью 480 px и отдаёт `/docimg/` (`docphotos.remote_photos`) |
| Центр реализации | с 22.10.2026 — из «Документов» лота: файл с «ФОТО» в названии или комментарии (обычно PDF), картинки вынимает `docphotos.attachment_photos`; договоры и сканы не берутся |
| АУКЦИОНПРО | фото на странице лота не нашлось — остаются фото агрегатора |
| остальные (НИС, ELECTRO-TORGI, Фабрикант, РАД, Центр реализации, Профит…) | фото в странице не отдают — остаются фото агрегатора |

- Откуда: проверка статусов (`status_refresh.py`) берёт фото со страниц, которые и так читает;
  остальные лоты ленты добирает `etp_collect.photo_pass` после каждого сбора (до 300 страниц за
  проход, повтор лота раз в 14 дней). Вручную, без ограничения:
  `docker compose exec api python -m app.etp_collect --photos`.
- Хранятся в базе: `lots.etp_photos` / `etp_photos_at` (импорт с ПК их не трогает).
- **Наборы фото** (`lots._photo_sets`): у лота несколько наборов по порядку — фото площадки, потом
  фото из выгрузки (агрегатора); у МЭТС фото площадки двумя наборами: через наш сервер и напрямую.
  Лента отдаёт все (`photo` + `photo_alts`, на экране лота `photo_sets`). Не открылось фото набора
  (площадка закрыла доступ, у пользователя VPN) — `app.js` сам берёт следующий; не открылось ничего —
  «Нет фото», а не пустой квадрат. Поэтому замена фото никогда не оставляет лот без фото.
- **Фото той же машины** (`lots._borrow_car_photos`): лоту без своих фото показываются фото другого
  лота той же машины (тот же VIN: запись «вне ЭТП» тех же торгов, прошлые торги) — лучший набор из
  имеющихся. 16.10.2026 так фото появились у 50 лотов.
- **Площадка закрыла доступ серверу** (3 ответа 403/429 подряд; 16.10.2026 так сделала МЭТС во время
  добора фото) — сервер 12 часов к ней не ходит вовсе (`status_refresh.note_response`, пауза в
  `miniapp/data/blocked_hosts.json`): сбор лотов, статусы, фото и прокси фото. Добор фото идёт с паузой
  3 секунды между страницами.
- **МЭТС не пускает зарубежные адреса** (403), и у пользователя с VPN её фото не открылись бы.
  Поэтому фото МЭТС мини-апп показывает через наш сервер: `GET /img?u=<адрес фото>`
  (`imgproxy.py`; только `https://m-ets.ru/download/…`, не открытый прокси; кэш —
  `miniapp/data/img_cache/`, файлы старше 45 дней удаляются).
- **Счётчик:** `python -m app.stats` на сервере и строка в еженедельной сводке с ПК
  (`GET /api/stats/photos`): «Фото в ленте: без водяных знаков N, со знаком площадки N, с агрегатора N,
  без фото N» — по первому фото лота; отдельно — сколько лотов показывают фото той же машины из
  другого лота.

## Выкладка

```
bash miniapp/deploy.sh      # из Git Bash в корне репозитория
```

Отправляет **закоммиченное** состояние (`git archive HEAD`: `lot_metrics.py`,
`bidding_schedule.py`, `miniapp/`) на сервер и пересобирает контейнеры. База и `.env` на сервере
не трогаются. Если изменился `Caddyfile` — перезапускает caddy.

После правок `app.js` или `style.css` увеличьте `?v=` в `frontend/index.html`, иначе Telegram
покажет старую версию из кэша. `index.html` отдаётся без кэша.

## Локальный запуск

```
python export_to_miniapp.py --dry-run     # выгрузка в miniapp_export_preview.json без отправки
python miniapp/run_local.py --import      # http://localhost:8000 + загрузка выгрузки в локальную базу
```

Конфигурация `honestlot` в `.claude/launch.json`. Ссылку на лот проверять так:

локально, а не на сервере.
