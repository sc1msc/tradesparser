# Уведомления и сбои

Что значит каждое автоматическое уведомление, что делать и как разбирать жалобы пользователей.
Действия на ПК и сервере выполняет владелец или разработчик; агент поддержки по этой странице
понимает, что происходит, и что сказать пользователю.

## Откуда приходят уведомления

Все уведомления с 16.10.2026 приходят от отдельного **бота уведомлений** (`HONESTLOT_NOTIFY_BOT_TOKEN`
на ВМ). С ПК они идут через сервер (`POST /api/notify`) и релей: прогон работает без VPN, а
`api.telegram.org` из России закрыт — с 11.10 по 16.10.2026 ни одно уведомление с ПК не дошло. Сервер
недоступен — ПК пробует отправить напрямую от @honest_torgi_bot (дойдёт только с VPN).

| Отправитель | Когда | Кому |
|---|---|---|
| бот уведомлений (с ПК через сервер) | в конце утреннего прогона, если были проблемы. Одно сообщение «HonestLot: прогон 11.10 07:00 - с проблемами» (или «УПАЛ») со списком «• …» и путём к логу | `NOTIFY_CHAT_ID` |
| бот уведомлений (с ПК через сервер) | раз в 7 дней — «HonestLot: сводка за 7 дн.» | `HONESTLOT_ADMIN_CHAT_ID` |
| бот уведомлений (с ПК через сервер, сессия Claude) | по понедельникам около 10:00 — «На связи Придирыч. Ревью кода HonestLot 19.10»: баги и риски в коде за неделю | `NOTIFY_CHAT_ID` |
| бот уведомлений (с сервера) | выгрузки не было больше 36 часов; повтор раз в сутки; «выгрузка с ПК снова пришла» | `HONESTLOT_ADMIN_CHAT_ID` |

Тишина — нормально: значит, проблем не было. Но если нет и еженедельной сводки — прогоны,
возможно, не запускались.

## Каталог уведомлений прогона

Текст уведомления начинается так, как в первой колонке.

| Уведомление | Что значит | Что делать | Видно пользователям |
|---|---|---|---|
| «Упал шаг N/7 (файл.py): … Дальнейшие шаги не выполнены.» | исключение в шаге, прогон остановлен | открыть лог `logs/pipeline-*.log`, найти traceback. Частая причина — обрыв связи с Google (`ConnectionAbortedError`, 10.10.2026). Разовый сбой — запустить `python run_pipeline.py` вручную или дождаться завтра | если упал шаг 1–6 — в приложении вчерашние данные (выгрузки не было) |
| «Сайт торгов не отвечает: первая страница поиска не загрузилась …» | агрегатор лежал | ничего, если разово. Повторяется — открыть ссылку поиска в браузере | новых лотов сегодня нет |
| «Поиск на сайте торгов прервался на странице N …» | часть страниц не загрузилась | ничего, догонит следующий прогон | часть новых лотов появится завтра |
| «Поиск на сайте агрегатора не отдал лоты (пустая первая страница) …» | агрегатор отдал пустую выдачу или сменил вёрстку поиска | открыть ссылку поиска: лоты есть — нужна правка `parse_search.py` | новых лотов нет |
| «Новых лотов нет N дн.: последний занесён ДД.ММ.ГГГГ …» | поиск отвечает, но новых лотов агрегатора в нём нет `NO_NEW_LOTS_ALERT_DAYS` (2) дня подряд — агрегатор перестал их публиковать (так было с 11.10.2026). Лоты с площадок это уведомление не глушат | открыть поиск без фильтров: самый свежий лот там тот же — проблема агрегатора, ждать. Лоты с площадок, где есть свой сборщик (ТоргГрупп), приходят и без него | новые лоты остальных площадок не приходят; уведомление — каждый прогон, пока не появятся |
| «Лоты с площадок: не записались в лист …» | сбой связи с Google при записи лотов, собранных сервером | ничего: придут в следующий прогон | эти лоты появятся на день позже |
| «Новые лоты: …», «Перепроверка публичных предложений: …», «Мини-апп, карточки лотов: …» + «карточек лотов подряд не прочитались … Проход остановлен» | 10 карточек подряд не прочитались: сайт лежит или сменилась вёрстка карточки | открыть пару карточек в браузере; если вёрстка — правка `parse_lot.py`/`nextjs_json.py` | статусы ПП, новые лоты или фото обновятся позже |
| то же + «не прочитались N из M карточек» | треть карточек не прочиталась | разово — ничего | то же |
| «Перепроверка публичных предложений: не записались статусы N лотов (сбой связи с Google)» | Google не принял запись | ничего, перепроверятся завтра | статусы этих лотов на день старше |
| «TRONK: месячный бюджет 1000 руб. - осталось …, оплачиваю N из M VIN» | бюджет месяца кончился | дождаться месяца или поднять `TRONK_MONTHLY_BUDGET_RUB` в `config.py` | у новых лотов пробег «~» по году |
| «Баланс TRONK … - хватит примерно на N дн. Пополните (lk.tronk.info)» | на счету TRONK мало денег | пополнить на lk.tronk.info | пока нет |
| «TRONK: справочник по VIN (vin_cache) не записался …» | купленный пробег не сохранился в справочник | следующий прогон может заплатить за эти VIN ещё раз; разово — ничего | нет |
| «Авто.ру просит капчу, её не решили за 10 мин …» | Авто.ру показал капчу, человека у ПК не было | ничего: оставшиеся лоты оценятся завтра. Если капча каждый день — запустить шаг 5 вручную и решить капчу (`python evaluate_autoru_browser.py`) | у новых лотов нет оценки и процента |
| «Авто.ру: 5 ошибок подряд (последняя: …)» | Авто.ру лежит или сменил форму | смотреть последнюю ошибку. «Не удалось найти поле VIN», таймаут ожидания ответа каждый день — форма изменилась, правка `autoru_valuation.py` (07–08.10.2026 так было из-за нового поля «Город продажи») | новые лоты без оценки |
| «Выгрузка в мини-апп не прошла: 409 … выгрузка скрыла бы N из M лотов ленты …» | срез вдвое меньше ленты: сбой пересборки среза или строки без номера лота. Сервер выгрузку не принял, мини-апп показывает прошлую | посмотреть лог шагов 3–4 и `lots_current_month`. Если сокращение настоящее — `python export_to_miniapp.py --force` |
| «Выгрузка в мини-апп: у N строк среза не определился номер лота, они не выгружены …» | в срезе ссылка нового вида (новая площадка или площадка сменила адреса) | правка `export_to_miniapp.lot_id_of` / `etp_lots.lot_id_from_url`; остальные лоты выгружены |
| «Выгрузка в мини-апп не прошла: …» | сервер мини-аппа не принял выгрузку | `https://honestlot.ru/api/health`; `docker compose ps` на ВМ; 403 — не совпадает ключ импорта | приложение показывает вчерашние данные |
| «Копия базы мини-аппа не скачалась: …» | не скачался бэкап на ПК | разово — ничего, на сервере есть свои копии | нет |

## Уведомления сторожа (с сервера)

| Уведомление | Что значит | Что делать |
|---|---|---|
| «HonestLot: выгрузки лотов с ПК не было N ч (последняя - …), мини-апп показывает устаревшие данные…» | прогон не дошёл до шага 7 больше 36 часов: ПК выключен, задача Планировщика выключена, сломан `.venv`, Python упал до уведомлений, или прогон каждый день падает | проверить ПК: включён ли, задача `\HonestLot\Pipeline` в Планировщике, последний лог в `logs/`. Запустить `run_pipeline_auto.bat` вручную |
| «HonestLot: выгрузка с ПК снова пришла (…)» | всё восстановилось | ничего |

## Уведомления проверки статусов (с сервера)

Шлёт `status_refresh.py` (бот уведомлений, получатель `HONESTLOT_ADMIN_CHAT_ID`).

| Уведомление | Что значит | Что делать |
|---|---|---|
| «…проверка статусов на сервере: не прочитались N из M карточек агрегатора…» | агрегатор лежит или закрыл доступ серверу | разово — ничего; повторяется — проверить сайт агрегатора с ВМ (`curl`). Пока статусы — по выгрузке с ПК, ПК перепроверит всё сам |
| «…проверка статусов на ЭТП: на <площадка> статус не распознан у N из M лотов — площадка отвечает ошибкой (HTTP 403)…» | площадка закрыла доступ серверу | для этих лотов работает статус агрегатора; если важно — проверять эту площадку с ПК |
| «…статус не распознан… — поменялась вёрстка страницы» | площадка поменяла страницу | правка разбора в `etp_status.py` |
| «HonestLot: лоты на площадках, где статус торгов мы пока не разбираем…» (раз в сутки, если появилась площадка или лотов заметно прибавилось) | список площадок без разбора и число лотов | если площадок с заметным числом лотов прибавилось — дописать разбор в `etp_status.py` |

## Уведомления сбора лотов с площадок (с сервера)

Шлёт `etp_collect.py` (бот уведомлений, получатель `HONESTLOT_ADMIN_CHAT_ID`), не чаще раза в
сутки на площадку.

| Уведомление | Что значит | Что делать |
|---|---|---|
| «…сбор лотов с площадок: не читается список лотов на <площадка> (ошибка … / список пуст)…» | площадка закрыла доступ серверу или сменила адреса | открыть список на площадке с ПК; адреса поменялись — правка `etp_lots.py`. Новые лоты с площадки пока только через агрегатор |
| «…на <площадка> не открылись N из M страниц лотов…» | площадка сбоит | разово — ничего, следующий проход дочитает |
| «…у N из M лотов не разобрались название, цена или срок… — поменялась вёрстка» | площадка поменяла страницу лота | правка разбора в `etp_lots.py` |

Пайплайн остановлен нарочно (отпуск) — убрать `HONESTLOT_ADMIN_CHAT_ID` из `.env` на ВМ и
перезапустить `api`, иначе напоминания каждый день.

## Еженедельная сводка

Пример (цифры условные):

```
HonestLot: сводка за 7 дн.
Прогонов: 7 (дней с прогоном: 7 из 7), без проблем: 5.
Потрачено на API за неделю: 120 руб. (TRONK за месяц: 340 из 1000 руб.)
Баланс TRONK: 2100 руб.
```

«Дней с прогоном» меньше 7 — ПК был выключен в эти дни.

## Еженедельное ревью кода

По понедельникам приложение Claude на ПК запускает сессию-ревьюера «Ревьюер Придирыч» (задача
`weekly-code-review` в разделе «Запланированные»). Она читает изменения кода за неделю и одну
часть кода целиком по очереди, ищет баги и риски и присылает короткий отчёт: «🔴 срочно»,
«🟠 важно», «🟡 мелочь», риски и что висит с прошлых недель. Ревьюер ничего не меняет и не
запускает пайплайн.

- Подробности по каждому пункту — в `reviews/<дата>.md` на ПК (папка не попадает в git:
  репозиторий публичный). Чтобы починить, сказать Claude: «исправь №2 из ревью 19.10».
- Отчёт не пришёл в понедельник — приложение Claude было закрыто: задача выполнится при
  следующем открытии. Запустить вручную — «Запустить» у задачи или `/weekly-review` в сессии
  в папке проекта.
- Пользователям не видно, к поддержке не относится.

## Симптомы у пользователей → диагностика

| Жалоба | Проверить | Вероятная причина |
|---|---|---|
| Приложение не открывается у одного | `http://84.201.144.182` у пользователя | VPN/DNS/сеть пользователя |
| Не открывается у многих | `https://honestlot.ru/api/health`; `docker compose ps`; срок сертификата | упал контейнер, домен, сертификат, ВМ |
| Заглушка «работает внутри Telegram» у всех | логи `api` (401 «неверная подпись initData») | `HONESTLOT_BOT_TOKEN` на ВМ не от @honestlot_bot |
| Бот не отвечает на /start | `docker compose logs bot`; проверка релея из `miniapp/README.md` | релей не пускает IP ВМ (403), упал сервис `bot`, Telegram недоступен |
| Нет новых лотов несколько дней | `logs/runs.jsonl`, последние логи, уведомления | прогон не запускается или падает на шаге 1 |
| Лот висит закрытым | статус в `lots` на ПК (`status`, `status_checked_at`) | аукцион (статус не перепроверяется) или агрегатор отстаёт |
| Цена не совпадает | `bidding_periods` лота в `lots`, график на экране лота, карточка на сайте | нули в графике, агрегатор отстаёт, этап сменился |
| Нет оценки у лота с VIN | `autoru_status` в `lots_current_month` | `ambiguous`/`no_price`/`no_mileage`, ошибка, капча, лимит 300 |
| Пробег явно не тот | `mileage_km`, `mileage_probeg_*` в `lots`, текст лота | ошибка разбора текста или источника |
| Битый не скрыт | название лота; `damage_check_cache.json` | признаки только в описании, фото не проверялись |
| Пропало избранное | `favorites` в базе по `telegram_id`; бэкапы | другой аккаунт Telegram; восстановление из копии |

## Ручной запуск после сбоя

```
python run_pipeline.py                 # весь прогон с вопросами yes/да
python run_pipeline.py --auto          # весь прогон без вопросов, с логом и уведомлением
python export_to_miniapp.py            # только выгрузка в мини-апп (если упала она)
python evaluate_autoru_browser.py      # только оценка Авто.ру (решить капчу в окне)
```

Шаги можно запускать по отдельности в порядке конвейера. Повторный прогон в тот же день дешёвый:
недавно проверенные публичные предложения пропускаются, уже оплаченные VIN не оплачиваются.
Если блокировка `logs/pipeline.lock` осталась от упавшего прогона — она считается зависшей через
8 часов, или удалите файл, убедившись, что прогон не идёт.
