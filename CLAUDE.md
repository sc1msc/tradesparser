# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A set of standalone Python scripts that scrape bankruptcy car auction lots (Moscow + Moscow Oblast) from a Next.js trade-aggregator site, enrich them with VIN decoding, mileage, and market valuations (Auto.ru, optionally TRONK/Avito), build themed selections, and publish a digest to a Telegram channel via Telegraph. **The only shared state between scripts is one Google Spreadsheet** (`config.SPREADSHEET_ID`), accessed through a service account (`service_account.json`).

Code comments, docstrings, and console output are in Russian. Every module has a long docstring explaining *why* it works the way it does. Read it before changing a script. Match that style.

**Wiki (`wiki/`, Russian)** is the knowledge base for the support agent that answers users in @honestlot_support_bot, and for newcomers: product, exact UI texts, how every number is computed, FAQ with ready answers, alert runbook, infrastructure. When you change user-visible behavior, UI texts, pipeline steps, alerts, or servers, update the matching wiki page in the same commit (the code-to-page map is at the end of `wiki/README.md`). Never put secret values in the wiki.

## Commands

No build, lint, or test suite. There is no git repo either. Each script runs directly and exposes a `run()` function:

```
pip install -r requirements.txt
playwright install chromium           # browser for evaluate_autoru_browser.py / evaluate_avito_browser.py
python sheets_writer.py               # check the Google Sheets connection
python run_pipeline.py                # full data pipeline (see order below)
python run_pipeline.py --auto         # same, unattended: what the daily Windows task runs
python run_pipeline.py --test-notify  # send a test Telegram notification
python main.py                        # any single step can also run on its own
python send_digest.py                 # publish to Telegram (manual, interactive choice of selection)
python tronk_valuation.py <VIN>       # one-off paid TRONK test, does not write to the sheet
```

Several steps prompt for `yes`/`да` confirmation on stdin (paid API calls, launching the browser) through `automation.confirm`. Playwright scripts run with `headless=False` on purpose (anti-bot); on an Auto.ru captcha the step waits `AUTORU_CAPTCHA_WAIT_MIN` minutes for a human, then stops.

**Daily automatic run** (since 2026-10-07): Windows Task Scheduler task `\HonestLot\Pipeline` runs `run_pipeline_auto.bat` (`run_pipeline.py --auto`) every day at 07:00 on the user's PC (catches up when the PC is turned on). Confirmations pass automatically; money is capped by the per-run limits and `TRONK_MONTHLY_BUDGET_RUB` (1000, month spend from the expenses ledger, applies to manual runs too). Problems go through `automation.alert` and are sent as one Telegram message at the end of the run. The run goes without VPN and api.telegram.org is blocked from Russia, so `automation.send_telegram` posts to the server (`POST /api/notify`, import token), which forwards via the relay with the separate notification bot (`HONESTLOT_NOTIFY_BOT_TOKEN` in `miniapp/.env`, recipient `HONESTLOT_ADMIN_CHAT_ID`; all server alerts use it too, `watchdog._send`); only if that fails, it tries @honest_torgi_bot directly (`TELEGRAM_BOT_TOKEN`/`NOTIFY_CHAT_ID`, works only with VPN). From 2026-10-11 to 2026-10-16 no PC alert arrived; a short summary every `PIPELINE_SUMMARY_DAYS`. A manual `run_pipeline.py` takes the same `logs/pipeline.lock` as `--auto` and refuses to start while another run holds it. Logs: `logs/pipeline-*.log` (30 days), run history `logs/runs.jsonl`. It runs on the PC, not the Yandex VM: from the VM Auto.ru shows a captcha right away and the Claude API is unreachable (checked 2026-10-06); Telegram is reachable from the VM only through the relay (see below). New problems a human should know about: call `automation.alert(...)`, not just `print`. Trade-site card fetches go through `main.CardFailures` (alert when a third of cards fail; stop the pass after `SITE_MAX_ERRORS_IN_ROW` in a row instead of retrying hundreds of cards for hours); use it in new loops over lot cards.

**Weekly code review** (since 2026-10-15): the Claude desktop app's scheduled task `weekly-code-review` (Mondays ~10:00, Auto mode, runs only while the app is open, otherwise on next launch) starts a Claude session that follows `.claude/skills/weekly-review/SKILL.md` (by hand: `/weekly-review`). It reviews the diff since the last review plus one code area in rotation, and runs `review_checks.py` (secrets in the public repo, syntax, tracebacks in `logs/`, Telegram send). It is read-only and writes only `reviews/` (gitignored: the repo is public): `reviews/<date>.md`, whose top part (above `<!-- telegram-end -->`) goes to `NOTIFY_CHAT_ID` via @honest_torgi_bot and whose details below are written for the session that fixes them, and `reviews/state.json` (last reviewed commit, area dates, open findings). For "исправь №N из ревью DD.MM", read that report's details first. When you add a module or rename an area, update the area table in the skill.

## Data flow (sheets = pipeline stages)

```
main.py ──► "lots" (raw, A..AM via sheets_writer + extra cols; AZ/BA/BB = brand/name/date from autodoc_decode.py, disabled - empty for new lots)
              │  fill_missing_mileage.py (paid TRONK probeg) writes mileage back into "lots"
              ▼
build_lots_processed.py ──► "lots_processed"   (FULL overwrite from "lots" every run; empty
              │                  brand/name/year filled from title via fill_missing_from_title.fill_rows)
              ▼
build_lots_current_month.py ──► "lots_current_month"  (applications_end within 30 days;
              │                  preserves extra/trailing columns by VIN across rebuilds)
              │  evaluate_autoru_browser.py adds autoru_* columns here (Playwright)
              ▼
build_lot_selections.py ──► "lots_top_gap", "lots_budget_1m", "lots_one_owner", ...
              ▼
send_digest.py ──► Telegram channel + Telegraph page (telegraph_publish.py)
```

`run_pipeline.py` runs the steps in a fixed order, and **the order matters**:
- The title-based brand/name/year fill used to be a separate step after `build_lots_processed`, and any standalone rebuild wiped it. It now runs inside `build_lots_processed`; `fill_missing_from_title.py` alone is only for manual use.
- `evaluate_autoru_browser` reads `mileage_km` from `lots_current_month`, so it must run after the mileage fill and both rebuilds.

Step 7 of `run_pipeline.py` is `fill_dtp.py` (since 2026-10-19, paid): ДТП by VIN from TRONK `dtp.ashx` (`tronk_dtp.py`) for every car VIN in `lots_current_month`, stored only in `vin_cache` (`dtp_*` columns, re-asked after `DTP_TTL_DAYS` = 180; errors retried), capped by `DTP_MAX_PER_RUN` and the shared `TRONK_MONTHLY_BUDGET_RUB` (1500 since 2026-10-19). Three outcomes: accidents list, `hasDtp: false` («ДТП не найдены»), error «Не удалось получить данные» = no data (no block in the app, not «clean»). Export sends `dtp` ({count, as_of, accidents with scheme ids}, accidents of another brand dropped); the app shows «ДТП: N» to everyone and dates + damage schemes (TRONK `img.ashx`, served via our `/img` proxy on a white backing) only with Pro (`locked("dtp")`, UI-only like filters).

Step 8 (the last) of `run_pipeline.py` is `export_to_miniapp.py`: it reads `lots_current_month`, downloads each lot card from the trade site for data the sheet lacks (all photos, the public-offer price schedule `bidding_periods`, trade form, status), caches it in `miniapp_details_cache.json` (gitignored, refreshed after `MINIAPP_DETAILS_REFRESH_DAYS`), and POSTs everything to the mini app server. It skips itself when `MINIAPP_API_URL`/`MINIAPP_IMPORT_TOKEN` are not set and never fails the pipeline.

Not in the pipeline (manual/side tools): `autodoc_decode.py` (VIN → Autodoc, writes brand/model/date into `lots` from column AZ, has its own inline config; **disabled since 2026-10-11** with `ENABLED = False`: Autodoc changed its API, and running it against the new one would mark rows `OK` with empty fields and could overwrite the columns right of its block. New lots get brand/name/year from the title only), `evaluate_tronk.py` / `evaluate_avito_browser.py` (their outputs are no longer read downstream; Auto.ru is the only market price used), `filter_beautiful_plates_gspread.py` (uses `plates_series.txt`, writes a `beautiful_plates` tab + xlsx), and `temp.py` (scratch). `check_completeness.py` (manual, since 2026-10-19) reports field coverage of the feed (photos, VIN, mileage, estimate, owners, specs, schedule, fresh status) per source from the newest `miniapp_backups/` DB, compares with the previous day, and exits 1 on a floor breach or a drop over 5 pp; it uses the backend's own `lots.is_open`. `check_damage_photos.py` (manual, paid Claude API, model in `config.DAMAGE_CHECK_MODEL`) looks at up to 4 photos of lots priced `DAMAGE_CHECK_MIN_GAP`% (40) or more below market and labels them `total` / `not_total` / `unclear` (only `total` counts as damaged); results in `damage_check_cache.json`, a review page in `damage_check_report.html`; `--dry-run` needs no API key. `export_to_miniapp.py` sends the verdict (`photo_verdict`, `photo_signs`) to the mini app.

## Key conventions and gotchas

- **`sheets_writer.py` schema is stale.** Its `COLUMNS` (A..AM) is used only by `main.py`, `evaluate_tronk.py`, and `evaluate_avito_browser.py`. The real `lots` sheet has more columns. Newer scripts (`build_*`, `fill_*`, `evaluate_autoru_browser`) bypass it and use gspread directly, addressing columns by header name or explicit column letter. Follow that pattern in new code. `ARCHITECTURE.md` describes the older three-stage design and doesn't cover the newer scripts.
- `sheets_writer.ensure_header()` rewrites row 1 of `lots` on connect. `SheetState` writes explicit ranges (`A5:AM5`) instead of relying on Sheets table auto-detection, which previously caused column shifts.
- `main.py` deletes lots whose application deadline passed `EXPIRED_LOT_DAYS` ago and skips `lot_id`s already in the sheet, so re-runs are idempotent.
- Scraping (`nextjs_json.py`): lot data is JSON embedded in `self.__next_f.push(...)` payloads, not HTML markup. `find_json_value` extracts a bracket-balanced fragment by key (`initialLots`, `initialMeta`, `lot`). Long strings (title, description) come as `"$80"` references to a separate `80:T<hex byte length>,<text>` chunk; resolve them with `resolve_text_ref`. VIN and plate are found in lot text by `lot_metrics.find_vin` / `find_plate`, one implementation for the parsers, `build_lots_processed` (fills empty VIN/plate of older rows) and the Auto.ru step: organizers type VINs with Cyrillic look-alikes and plates with Latin letters (`X707HX197`) or glued to the next word.
- Enrichment scripts write only into empty cells, or retry only rows whose status column isn't `ok`/`no_data` (`error: ...` gets retried). They leave a value empty rather than write a guess.
- **Paid APIs:** TRONK (`tronk_valuation.py`, `tronk_mileage.py`) charges per request. Per-run caps live in `config.py` (`TRONK_MAX_PER_RUN`, `MILEAGE_MAX_PER_RUN`) and are the real budget guard. Don't raise them or remove confirmation prompts casually.
- Mileage fallback used by the valuation scripts: lot card → TRONK reading extrapolated to today (`ANNUAL_MILEAGE_KM`) → `(current_year - year) * ANNUAL_MILEAGE_KM`. Mileage above `lot_metrics.MAX_PLAUSIBLE_MILEAGE_KM` (1M km) counts as missing: `fill_missing_mileage.py` marks the TRONK result `suspicious` and doesn't write `mileage_km`, and the Auto.ru step and the mini app fall back to the year estimate.
- **Expenses** (`expenses.py`) are kept on the PC, not in the Google Sheet: `expenses/ledger.csv` (";" and decimal comma for Russian Excel, editable by hand) and `expenses/report.html` (rebuilt at the end of `run_pipeline.py`, or `python expenses.py`). Paid TRONK steps record the real charge as the balance difference from the free `profile` method (falls back to requests x price); each pipeline run snapshots the TRONK balance and adds `config.FIXED_MONTHLY_COSTS` once a month. New paid steps should call `expenses.record_tronk` in a `finally`. `expenses/` is gitignored.
- `fill_missing_mileage.py` pays once per VIN: a VIN already checked in another row or in `vin_cache` is copied for free, and duplicate VINs among candidates share one request. `MILEAGE_MAX_PER_RUN` limits unique VINs.
- **`vin_cache` sheet** (`vin_cache.py`): per-VIN store of TRONK mileage (forever) and Auto.ru estimates (`AUTORU_ESTIMATE_TTL_DAYS = 60`), so paid/slow data survives lot deletion and relistings. Step 2 reads/writes it; step 4 saves the old slice's estimates into it, fills estimates from it and clears expired ones; step 5 writes new estimates. Writes are batched (`flush`) because of the Sheets write quota. One-time migration: `python vin_cache.py --backfill`.
- Auto.ru estimates with `autoru_uncertainty_percent >= 90` or status `ambiguous` stay in selections but are labeled "оценка может быть неточной" (`lot_metrics.estimate_is_uncertain`), both in the digest (`send_digest._fmt_gap_label`) and in the mini app.
- Adding a new selection takes three edits: a `build_XXX` filter in `build_lot_selections.py`, a registration in its `BUILDERS`, and a matching `key` entry in `selections.py` (sheet name + digest texts).
- **Public offers (публичное предложение)** have a stepped price schedule. `lots.bidding_periods` holds it as compact JSON `[[bid_end, price], ...]`, while `lots.applications_end` stays the *final* deadline (used by `remove_expired_lots`): the later of the site's `stages.end_bid_time` and the last period's end (`bidding_schedule.final_deadline`), since the two don't always match. The current period's price/deadline is computed by time in `bidding_schedule.py`: `build_lots_processed.py` substitutes it into `price_current`/`applications_end`, and `send_digest.py` recomputes it at send time. `main.py` re-reads cards of ongoing public offers (skipping ones checked since the aggregator's nightly update and within `PUBLIC_OFFER_REFRESH_HOURS`) to refresh `status` (bids end the trade early), and `build_lots_current_month.py` drops closed statuses. `DATA_UPDATES.md` (Russian) explains in detail what is written once vs. refreshed, and why.
- **Numbers must be written as numbers.** gspread 6 writes RAW, so a Python string `"450000"` lands in the cell as text, and every rebuild reads sheets as strings. Before writing a sheet, call `sheets_writer.numify_rows(header, rows)` (columns listed in `sheets_writer.NUMERIC_COLUMNS`); don't switch to `USER_ENTERED` (it would turn `applications_end` into Sheets dates and `+7…` phones into numbers). `fix_numeric_cells.py` converts text-numbers already in the sheets (including `vin_cache`), in place, and clears leftover percent formats from numeric columns: a cell keeps its format across rebuilds, and a percent-formatted `estimated_mileage` of 300000 reads back as `"30000000%"` (`to_number` understands that form).
- **Lot kind** (`lot_metrics.lot_kind`, computed in `build_lots_processed.py` from `lots` title + description into column `lot_kind`): `car`, `multilot` (2+ distinct VINs, not counting body/chassis numbers), `rights` (право требования), `share` (доля). Rights and shares are dropped from `lots_current_month` (so from selections, the digest, Auto.ru and the mini app). Multilots stay in the slice but get no Auto.ru estimate and no `% below mkt`, don't go into selections, and show in the mini app with a "Мультилот" tag and a lot-type filter.
- `% below mkt` is computed in `build_lot_selections.py` (step 7, after the Auto.ru step) from `autoru_price_low/high` vs `price_current` and written both into `lots_current_month` (the main column users look at) and into the selection sheets. No other script fills it; a sheet formula there would be wiped by the next `build_lots_current_month` rebuild.
- Secrets are kept out of git (see `.gitignore`). The TRONK key, Telegram bot token, and `SPREADSHEET_ID` live in `local_secrets.py`, which `config.py` imports (template: `local_secrets.example.py`). Never hard-code keys into `config.py` or scripts. Also ignored: `service_account.json`, `telegraph_token.txt` (cached Telegraph token), and `browser_profile/` (the persistent Playwright Chromium profile).

## Mini app (`miniapp/`)

The Telegram Mini App "honestlot" for end users: a FastAPI + SQLite backend and a no-build vanilla JS frontend, both in one Docker image behind Caddy. See `miniapp/README.md`.
- **"Скрыть битые"** (mini app filter, on by default) hides lots with *total* damage only: `lot_metrics.total_damage_keywords` (годные остатки, разукомплектован, сгоревший, затоплен, нет двигателя...) or photo verdict `total`. "После ДТП" / "битая" only get the ⚠ badge; "не на ходу" is not damage (dead battery). Don't match bare "БИТ" - it hits "арбитражный".
- `lot_metrics.py` (repo root) holds the one `% below mkt` formula and the damage keywords. Both `build_lot_selections.py` and the backend import it, and the Docker image copies it. Don't duplicate the formula.
- The backend also imports `bidding_schedule.py` (copied into the image like `lot_metrics.py`) and computes the current price/deadline with `effective_price_and_deadline` at request time, because a period can change between daily imports. `export_to_miniapp.py` sends status and `bidding_periods` from the sheet, and for public offers sends the *final* deadline (`final_deadline` of the card's `end_bid_time` and the schedule), not the sheet's current-period `applications_end`. The details cache is only for photos, description, trade form, platform and `end_bid_time`.
- Brand/model cleanup (aliases like VAZ→Lada, junk from title parsing) happens in `miniapp/backend/app/lots.py`, not in the sheet. Most lots get brand/model from Auto.ru (codes like FORD/FOCUS, BMW/5ER, shown as "5 серии", "M-класс"); `export_to_miniapp.py` sends `model_source` and the title-parsed `title_brand`/`title_model`, and `lots.build_catalog` learns a model dictionary (plus spellings like "Солярис"→SOLARIS) from Auto.ru lots to snap title-parsed models of lots without an estimate (`snap_model`). After that `catalog.py` (since 2026-10-18) applies manual fixes from the DB table `catalog_fixes`, model families (owner's decision: variants of one model are one model - Lada 2121/2131/Niva Legend → Niva, 2170 → Priora, GAZ 3302/2705 → ГАЗель) and uniform labels (RAV4, Santa Fe). The watchdog thread sends the admin a monthly catalog anomaly report; the owner sorts junk by hand with `python -m app.catalog fix|rename|ok`. Text search (`lots.text_matches`) matches word prefixes, Russian brand names, joined/hyphenated spellings and sound-alike model words (`_search_index`); saved searches must use the same function.
- The frontend has no build step: bump `?v=` in `miniapp/frontend/index.html` after changing `app.js`/`style.css`.
- **Car model** (`lots.py`): lots of the same car (`lot["car"]` = 17-char VIN of a `car`-kind lot) are grouped. Parallel open listings show as one feed card (`_primary_key`: cheapest, nearest deadline, ETP over "вне ЭТП"; `listings` = count); the lot screen shows other platforms and the car's trade history. **Favorites follow the car**: `favorites` stores `lot_id` + `vin`, `favorites_list` shows the car's current lot with `fav_state` (open/awaiting/done/failed/cancelled/suspended), `relisted`, and `archived` after `FAVORITE_ARCHIVE_DAYS = 60`. Removing a favorite removes the whole car.
- **Telegram from the VM goes through a relay.** The Russian ISP blocks api.telegram.org both ways (webhooks don't arrive either). A VPS in Amsterdam (VDSina, `89.124.97.131`, set up by `relay/setup.sh`) runs Caddy that only accepts the VM's IP and forwards to api.telegram.org. Server code calls the Bot API only via `app/telegram.py` (`HONESTLOT_TELEGRAM_API` in `.env`; `call(method, http_timeout=..., **params)` - not `timeout`, which is a Bot API parameter). The bot is the `bot` service (`app/bot.py`, long polling, deletes the webhook on start). User data must not be stored on the relay (152-FZ). The PC still talks to Telegram directly.
- Import watchdog (`app/watchdog.py`, a background thread in `api` like the backup; `bot` has no DB access): if the newest `lots.updated_at` (set only by import) is older than 36 h, the server messages `HONESTLOT_ADMIN_CHAT_ID` via the notification bot (`watchdog._send`), daily while stale, once on recovery. It covers runs that never started (PC off, broken `.venv`), which `automation.alert` can't report. Disabled without the variable.
- **Payments (Pro subscription)** are built but off: without `HONESTLOT_PAYMENTS_ENABLED=1` `/pay` and `/api/pay/*` return 404. `billing.py` (plans, auto-renewal thread, API), `pay_providers.py` (ЮKassa + `fake` for local tests), `mailer.py` (all payment communication is e-mail only), pages in `frontend/pay/` on the site, not inside the mini app (Telegram/Apple rules). On the VM payments are on (`HONESTLOT_PAYMENTS_ENABLED=1` since 2026-10-13); `billing.is_pro` feeds `/api/me` `pro`, which gates filters and favorites (see Web version). How to enable and the provider comparison: `wiki/payments.md`. Test with the fake provider locally, never with real keys on the VM. Public pages for ЮKassa moderation (`app/site.py`, templates in `app/site_pages/`): `/pro`, `/offer`, `/privacy`, `/requisites` (noindex; seller name/INN only from `.env` `HONESTLOT_SELLER_*`, the repo is public). Explicit routes, not `/{page}`, so they don't shadow the mini app's static files.
- **Web version** (since 2026-10-13): honestlot.ru in a regular browser runs the same `app.js` (`WEB` = `Telegram.WebApp.platform == "unknown"` outside localhost). Login is required (owner's decision): Telegram Login Widget -> `POST /api/web-login` -> 30-day token (`auth.make_web_token`, `Authorization: web <token>`, `localStorage hl_web_token`); same user as the mini app, so favorites are shared; `/pay` accepts the same token. The root is `noindex`. ЮKassa requires that the paying site doesn't send users to Telegram, so site buttons point to `/`, not to the bot. Pro gate (web since 2026-10-13, the Telegram mini app too since 2026-10-15, `proLocked` in `app.js`): without Pro (`/api/me` `pro: false`, present only when payments are on) filters and favorites open a Pro sheet (`showPaywall`, events `paywall`/`paywall_go`); on the site it has «Перейти на Pro», inside Telegram only «Понятно» (no payment button or link: Telegram 6.2 / Apple 3.1.1). UI-only, the API doesn't enforce it.
- Backups: the server copies its SQLite DB daily (`backup.py`, 7 kept in `miniapp/data/backups/`), and step 7 downloads a fresh copy to `miniapp_backups/` on the PC (`GET /api/backup`, import token, 7 kept). Users, favorites and events exist only in that DB.
- `GET /api/watchlist` + `POST /api/lot-status` (import token): step 7 re-reads cards of favorited lots past their deadline without a final status and sends the statuses.
- **Trade status on the ETP** (since 2026-10-15, owner's decision): the server itself (`app/status_refresh.py`, a thread in `api`, 05/11/16/21 MSK) re-reads aggregator cards (`parse_lot.py`) and the lot page on the trading platform (`etp_status.py`, parsers by platform engine) for open public offers and favorites without an outcome. Results go to `live_*`/`etp_*` columns that import never touches; `lots._apply_live` makes an ETP outcome win over the stale aggregator status, `pending` hides the lot without closing it. The PC pulls them in step 1 (`GET /api/lot-statuses` -> `main.pull_server_statuses`, sheet columns `etp_url`/`etp_status`/`etp_checked_at`) and re-reads itself only what the server did not check. The image copies `etp_status.py`, `parse_lot.py`, `nextjs_json.py` (Dockerfile, deploy.sh). Alerts (aggregator unreadable, a platform parser stopped recognizing, daily list of platforms without a parser) go to `HONESTLOT_ADMIN_CHAT_ID`. New platform: add its engine to `etp_status.py`.
- **Lots straight from the ETPs** (since 2026-10-16, owner's decision: together with the aggregator, not instead): the server (`app/etp_collect.py`, a thread in `api`, 06/14/20 MSK) walks the platforms in `etp_lots.COLLECTORS` (root module, copied into the image; ТоргГрупп, МЭТС and since 2026-10-19 ЦДТ via its JSON API `webapi.torgi.cdtrf.ru` and Lot-online via the RAD catalog `catalog.lot-online.ru` (region + «Имущество должников» filters); МЭТС answers only Russian IPs, so the PC under VPN gets 403 - fetch through the VM when developing), skips lots already in the feed (same ETP URL), reads new ones fully (lot page + trade page, original photos, ЕФРСБ number) into the `etp_lots` table. **Only the PC writes the Google Sheet**: step 1 pulls `GET /api/etp-lots` (`main.pull_etp_lots`) and appends missing lots in batches (`SheetState.append_many`); `etp_lots.Dedup` skips the same ETP URL, the same VIN of an open lot, or the same title + start price, and new aggregator lots already received from an ETP are skipped and remembered in `etp_duplicates.json` (gitignored). The ETP pull runs **before** the aggregator search, and `SheetState.records` (the sheet snapshot the dedup uses) gets every lot appended in the run, so the same listing arriving from both sources in one run stays one row. `POST /api/import` refuses (409) a payload that would hide more than half of a feed of 100+ lots (`?force=1` / `export_to_miniapp.py --force`), and export alerts on slice rows without a lot id instead of dropping them silently. Row = one listing (one trade lot), car = VIN. ETP lot ids are `9_000_000_000 + platform code * 10^8 + platform lot number` (`etp_lots.lot_id_for`; never change `PLATFORM_CODES`), `url` is the ETP page (`lots_current_month` has no `lot_id` column: derive ids from `url` with `export_to_miniapp.lot_id_of` / `etp_lots.lot_id_from_url`, not the aggregator `/lot/<id>` regex alone); their details cache entries come from the pull (export never fetches them from the aggregator), and `status_refresh` reads their ETP page instead of an aggregator card. The «Открыть лот на сайте торгов» button: `etp_url` (normalized by `etp_status.normalize_etp_url`: Профит's old search links redirect to its home page, the new trade page is `/<kind>/<number>`), else `efrsb_url` (`etp_status.efrsb_link`: the EFRSB announcement on the new fedresurs.ru, since old.bankrot.fedresurs.ru refuses foreign IPs) labeled «Открыть объявление на Федресурсе», else the aggregator; an ETP page answering 404 gets `etp_state = missing` and the button falls back to EFRSB. New platform: a class in `etp_lots.py` + `COLLECTORS` + `PLATFORM_CODES`.
- **Photos from the platforms** (since 2026-10-16): aggregator photos carry its watermark, so the server stores photos read from the ETP lot page (`etp_lots.page_photos`; `PHOTO_KIND`: ТоргГрупп originals, МЭТС/ЦДТ with the platform's own mark) in `lots.etp_photos` (import never touches it; written by `status_refresh` from pages it already reads and by `etp_collect.photo_pass`, 300 pages/pass, 14-day recheck, `python -m app.etp_collect --photos` for a full pass), and `lots._photo_sets` puts them first, keeping the aggregator photos as a fallback set (owner's priority: 1) a photo on as many lots as possible, 2) as few aggregator watermarks as possible); `app.js` (`thumbBox`, `gallery`) switches to the next set when an image fails and shows «Нет фото» only when all fail. Lots without photos borrow the best set from another lot of the same car (`_borrow_car_photos`). A host that answers 403/429 three times in a row is paused for 12 h for every server request (`status_refresh.note_response`/`check_paused`, `blocked_hosts.json`; МЭТС banned the VM on 2026-10-16 during the photo backfill). ЦДТ trades without photos on the page get them from the trade's documents (since 2026-10-21, `app/docphotos.py`: docs named «фото»/«авто»/«ТС» or image files, scans like ПТС/СТС/договор/акт skipped; PDF images extracted with pypdf, stored next to the DB in `doc_photos/` with thumbnails, served by `GET /docimg/<sha1>.jpg`, kind `original`); `status_refresh` must not overwrite them with an empty CDT page. МЭТС blocks foreign IPs, so its photo URLs are rewritten to our `GET /img?u=` proxy (`imgproxy.py`, whitelist `https://m-ets.ru/download/`, disk cache 45 days).
